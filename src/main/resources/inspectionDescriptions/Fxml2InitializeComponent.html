Reports FXML code-behind classes with a construction path that does not call initializeComponent().

A class is a code-behind class when an FXML file exists in the project with fx:subclass pointing to that class. The compiler-generated base class provides initializeComponent(), which must be called in the constructor to instantiate the scene graph declared in the FXML file.

A construction path is satisfied when the call appears in the constructor itself or in a constructor it delegates to, through Java this(...) and super(...) calls or Kotlin this(...) delegation. In Kotlin, an init block also satisfies every path. A class that declares no constructor at all is reported on the class name, because its implicit constructor cannot call initializeComponent().

A quick-fix inserts the call as the first statement of the reported constructor, or adds a constructor (Java) or init block (Kotlin) when the class declares none.

Example (problematic):

public class MyControl extends MyControlBase {
    public MyControl() {
        // initializeComponent() not called: scene graph never created
    }
}

Fix: call initializeComponent() in the constructor:

public class MyControl extends MyControlBase {
    public MyControl() {
        initializeComponent();
    }
}

To suppress this warning for a specific constructor or class, add @SuppressWarnings("Fxml2InitializeComponent").
